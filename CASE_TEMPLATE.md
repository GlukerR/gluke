# Шаблон кейса проекта — GLUKE

По этому шаблону собираются новые кейсы на сайт. Данные для заполнения берутся из папки `68_COMPANIES` (Obsidian: `<Компания>/данные/кейс.md`, `профиль.md`, `карточка.md`, `переписка/`), рендеры — из папок портфолио (`D:\3D\portfolio\...`).

---

## 1. Файлы

Один кейс = два файла (RU и EN):

```
content/projects/ru/<slug>.md
content/projects/en/<slug>.md
```

`<slug>` — короткое имя латиницей, строчными буквами и дефисами (например `wiederkraft`, `kiparis`, `house-guru`).

Существующие кейсы (для образца): `getic`, `kiparis`, `wiederkraft`, `house-guru`.

Медиа-файлы кладутся в:

```
public/media/projects/<slug>/
```

> ⚠️ Каждый файл медиа должен быть добавлен в список синхронизации `scripts/sync-media.mjs` (пара `source` (имя файла) → `target`). Файлы, которых нет в этом списке, не попадут в прод при синхронизации.

## 3. Поля по-порядку (важно)

| Поле | Что писать |
|---|---|
| `title` | Название кейса: «Цифровой каталог оборудования WiederKraft» |
| `description` | 1–2 предложения с цифрой объёма («Более 50 оптимизированных 3D-моделей…»). Идёт в карточку на главной |
| `position` | Порядок на странице «Проекты». Новый кейс ставится **последним** (больше текущего номера) |
| `categories` | Профили кейса (массив, 1–2 значения): `orgtech` (оргтехника и ИТ), `industrial` (промышленность и крупные объекты), `furniture` (мебель и интерьеры), `gameready` (геймреди — когда появятся такие кейсы). Кейс может лежать в двух профилях сразу — файл контента один, он показывается в обеих категориях |
| `period` | Только годы, без точных дат: `2024-2026`. У завершённых — последний год работы |
| `services` | 2–4 услуги. **Первые 2 показываются на карточке главной** — ставь на первое место самые показательные. ⚠️ Общие услуги (3D-моделирование по образцу/чертежам, каталожная визуализация, рендеры и т.п.) — это база, которая подходит почти всем кейсам, поэтому **не ставь их первыми**: на первые места идут уникальные/продающие услуги конкретного проекта (анимация, симуляция ткани, веб-вьювер, видео-инструкции, взрыв-схемы и т.п.), общие — следом |
| `period` в карточке | В карточке проекта годы (`period`) выводятся **в нижней строке слева, напротив «СМОТРЕТЬ КЕЙС →»** (кнопка прижата вправо). Так единообразно во всех карточках — ничего дополнительно настраивать не нужно, компонент `ProjectCard` делает это сам |
| `about` | Текст «О проекте» вместо списка. 2 абзаца: что делали + результат. Важно: в тексте не должно быть незакрытых кавычек-апострофов, ломающих YAML (см. раздел 5) |
| `metrics` | Ровно 3 показателя. Формат: большое значение (цифра или короткое слово) + подпись. Примеры: `20+`/`моделей оборудования`, `взрыв-схемы`/`внутреннее устройство товаров`, `3D-модели`/`по физическим образцам`, `300 DPI`/`подготовка материалов для печати` |
| `cover` | Обложка кейса: **16:9, 1680×945, JPEG ≤200 КБ**. Объект по центру с полями сверху/снизу (на карточках кадрируется до 16:10) |
| `media` | Галерея «Материалы проекта». **Первая и последняя записи всегда на всю ширину** сами по себе (правило галереи); обычные идут парами; `wide: true` — растянуть любой другой элемент; `triple: true` — квадратные картинки собираются по 3 в ряд на всю ширину (без обрезки, сохраняют квадрат) |

### Media — режимы видео

> **Правило: на сайте только два варианта видео.** Решает наличие звука в файле:
> 1. **В видео есть звук** (озвучка, диктор, интересный звуковой ряд) → `autoplay: true` + `loop: true` (+ `poster`): автозапуск + луп, звук по умолчанию выключен, но **контролы и значок mute видны** — посетитель может включить звук.
> 2. **В видео нет звука** → только `loop: true`: **никакого UI**, autoplay + muted + loop, чистая зацикленная анимация.
>
> Варианта «просто видео с контролами по нажатию» (без флагов) быть не должно — все видео автозапускаются и зациклены.

| Флаги | Поведение | Когда |
|---|---|---|
| `loop: true` | Фоновая зацикленная анимация: без контролов, autoplay + muted + loop, рамка по пропорциям видео. Для квадратных анимаций — `1280×1280` | Видео **без звука** |
| `autoplay: true` (+ `loop: true`, `poster`) | Автозапуск + луп, звук выключен, контролы и значок mute видны сразу | Видео **со звуком** (можно включить) |
| `poster: <путь>` | Кадр-заставка до старта видео | Для видео со звуком |
| `startAt: <секунды>` | Начать воспроизведение не с 0:00, а с указанной секунды | Когда два ролика в галерее стартуют синхронно и их нужно развести |

## 4. Подготовка рендеров

Правила, чтобы сайт грузился быстро и выглядел ровно:

> **Главное правило: новые изображения всегда пережимаются по образцу уже лежащих в этой же галерее** — тот же формат (JPEG/PNG), та же сторона (например 1680px), та же плотность файла (взвесь на глаз: сосед ~150–800 КБ → новый должен быть в этом же диапазоне). Смотри на соседние записи в `media` и повторяй их параметры.

- **Фото/рендеры:** JPEG, ширина/высота по большей стороне **не больше 1680px**, качество `-q:v 4`. Исключение — панорамы (можно 2880 по большей стороне, JPEG или PNG).
- **Прозрачные продуктовые PNG** (швабры, мебель на белом/прозрачном фоне): оставлять PNG, квадратные — 1680×1680, как соседний PNG в галерее (не конвертировать в JPEG: на тёмной теме не должно быть белых квадратов).
- **Обложка:** **16:9, 1680×945, JPEG ≤200 КБ**. Объект по центру с полями сверху/снизу — на карточках обложка кадрируется до 16:10.
- **Квадратные loop-анимации (без звука):** MP4 (H.264), **1280×1280**, без звука → в кейсе только `loop: true`.
- **Промо-видео (со звуком):** MP4 (H.264), 1920×1080 (или 1920×1016), со звуком, постер-кадр → в кейсе `autoplay: true` + `loop: true` + `poster`.

Команда (пример):

```bash
# изображение: 1680px по большей стороне, хорошее качество
ffmpeg -y -v error -i "исходник.png" -vf scale=1680:-2 -q:v 4 "public/media/projects/<slug>/<имя>.jpg"

# видео: пережать квадратную анимацию в 1280×1280
ffmpeg -y -v error -i "исходник.mp4" -vf scale=1280:1280 -c:v libx264 -crf 20 -an "public/media/projects/<slug>/<имя>.mp4"
```

- В файле кейса всегда указывай реальные `width`/`height` получившегося файла (проверь `ffprobe`).
- Имена файлов: латиницей, строчными, дефисы (`kiparis-sofa-mustard.jpg`).
- `alt` — описание того, что на картинке (важно для доступности и SEO).

## 5. Подводные камни (проверь!)

- **PNG с битым EXIF не читается ffmpeg** («invalid TIFF header in EXIF data»). Если так случилось — используй ImageMagick: `magick "файл.png" -resize 1680x1680 -strip "цель.png"` (он читает несмотря на предупреждение).
- **Двоеточие в alt-тексте ломает YAML.** Если в описании есть `: ` (двоеточие + пробел), бери строку в кавычки: `alt: 'Шиномонтажный станок на синем фоне: слева чертёжные проекции'`. Иначе YAML обрежет запись и `wide: true`/следующие поля «отвалятся» без ошибки.
- **Кэш контента** иногда слетает на этой машине (страница пустеет или показывает старое). Лечится: `rm -rf .data/content` в папке проекта + перезапуск dev-сервера.
- После правок схемы (`content.config.ts`) сервер надо **перезапускать**; правки только в `content/` подхватываются горячо.
- Новые медиа-файлы обязательны в `scripts/sync-media.mjs`.
