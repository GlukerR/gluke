# Справочник разработчика — GLUKE

Единая точка входа по коду сайта. Собран из `README.md`, `CASE_TEMPLATE.md`,
`docs/content-decisions.md` и практики разработки. Если документ противоречит

## 1. Стек и требования

- **Nuxt 4** (`app/`-структура), **Vue 3 Composition API**, **TypeScript** (strict, `typeCheck`).
- **Nuxt UI 4** (включает Tailwind CSS) — компоненты и токены тем.
- Модули: `@nuxt/content` (Markdown/yml → SQLite, коннектор `better-sqlite3`),
  `@nuxt/image`, `@nuxt/fonts` (Manrope), `@nuxtjs/i18n`, `@nuxtjs/robots`,
  `@nuxtjs/sitemap`, `nuxt-schema-org`.
- **ESLint** flat config + ESLint Stylistic: 2 пробела, одинарные кавычки, без `;`.
- 3D: `three` + `@types/three` (вьювер — `ProjectModelViewer.vue`).
- Node ≥ 22 (`.nvmrc`), pnpm (packageManager `pnpm@11.18.0`).

## 2. Команды

```bash
pnpm dev          # dev-сервер (по умолчанию :3000; на этой машине принято :52972)
pnpm build        # прод-сборка
pnpm generate     # статическая генерация
pnpm preview      # превью прод-сборки
pnpm lint         # ESLint
pnpm lint:fix     # ESLint autofix
pnpm typecheck    # nuxt typecheck (vue-tsc)
pnpm check        # lint + typecheck + build
```

Запуск с портом: `pnpm dev --port 52972`.

> ⚠️ Не запускай два `pnpm dev` одновременно: оба делят
> `.data/content/contents.sqlite` и могут её сломать (страницы → 500).

## 4. Как устроен сайт

- **Главная** (`app/pages/index.vue`) собирает секции из `app/components/home/*`,
  контент — из `content/site/{ru,en}.yml` (hero, about, services, stats, process).
- **Список проектов** (`projects/index.vue`) — карточки `ProjectCard`,
  данные из коллекции `projects` (`content/projects/*.md`).
- **Кейс** (`projects/[slug].vue`) — hero (`ProjectDetailHero`), метрики и услуги
  (`ProjectDetailOverview`/`ProjectDetailScope`), галерея (`ProjectMediaGallery`
  + `ProjectMediaItem`), переходы (`ProjectPager`).
- **i18n**: EN — без префикса (дефолт), RU — под `/ru`
  (`strategy: prefix_except_default`). Строки — `i18n/locales/*.ts`,
  `baseUrl` — из `NUXT_SITE_URL`.
- **Темы**: `@nuxt/ui` + Nuxt Color Mode; тёмная по умолчанию.
  Токены и переходы — в `app/assets/css/main.css`.

### Автоимпорт компонентов (важно!)

Nuxt автоимпортирует SFC, **добавляя префикс из имени папки**:

- `app/components/site/SiteHeader.vue` → `<SiteHeader>`
- `app/components/projects/ProjectCard.vue` → `<ProjectsProjectCard>`
- `app/components/projects/ProjectModelViewer.vue` → `<ProjectsProjectModelViewer>`

Ссылаться на компонент без префикса (`<ProjectModelViewer>`) — тихая ошибка:
компонент не рендерится. При создании файла сверь имя в шаблоне.

## 5. Контент: кейсы

Схема — `content.config.ts` (коллекция `projects`), поля описаны в
`CASE_TEMPLATE.md`. Основное:

- Один кейс = **два файла**: `content/projects/ru/<slug>.md` и `en/<slug>.md`.
- Медиа — в `public/media/projects/<slug>/`; папка `public/` отдаётся
  статикой, поэтому новые файлы попадают в прод автоматически.
- Поля: `title`, `description`, `client`, `industry`, `categories`
  (`orgtech|industrial|furniture|gameready`), `position` (новый кейс — последним),
  `featured`, `status`, `period`, `engagement`, `services` (первые 2 — на карточке
  главной, самые продающие), `metrics` (ровно 3), `cover` (16:9,
  1680×945, JPEG ≤200 КБ), `media`, опционально `model` (3D).
- `## Задача / Ход работы / Результат` выводятся на странице кейса: первый абзац
  «Задачи» стоит рядом с услугами, остальное — в свёрнутом блоке «Подробнее о
  проекте» (`app/utils/project-story.ts` делит тело, дублирования нет).
- Поля `about` больше нет: оно дублировало «Задачу» и удалено из схемы и кейсов.
- `updated` не пишется руками: перед коммитом правок контента запусти `pnpm lastmod`.
  Скрипт берёт дату из git, а sitemap отдаёт её как `lastmod`. Считать дату на
  Vercel нельзя — там поверхностный клон, `git log` вернёт одну дату на все файлы.

### 3D-модель в кейсе (`model:`)

```yaml
model:
  src: /media/projects/softlogic/sc-imvs-rm3-model-01.glb
  alt: '…'
  width: 1680
  height: 945
  autoRotate: true          # автоповорот (по умолчанию true)
  emissivePulse: 5          # макс. интенсивность пульсации свечения (дефолт 5)
  emissivePulseHz: 0.7      # частота пульсации, Гц (дефолт 0.7)
  metalness: 0.88           # множитель металличности (дефолт 0.88)
  diffuseLift: 30           # подъём «чёрного» диффузной текстуры (дефолт 30)
  rotation: 180             # разворот модели вокруг Y, градусы (дефолт 0)
  autoRotateSpeed: 1.2      # скорость автоповорота (дефолт 1.2)
  environmentIntensity: 0.5 # интенсивность студийного окружения (дефолт 0.5)
  hemisphereLight: 0.5      # полусфера (дефолт 0.5)
  keyLight: 0.8             # ключевой свет (дефолт 0.8)
  fillLight: 0.4            # мягкая подсветка (дефолт 0.4)
```

Параметры вьювера — **данные, а не код**: движок один
(`ProjectModelViewer.vue`), каждая модель переопределяет дефолты через
frontmatter. Требования к моделям (GLB, Draco, WebP-текстуры ≤2K, локализация
всех файлов) — в `docs/3d-viewer-spec.md` §5.

### Конфигуратор машины в кейсе (`configurator:`)

```yaml
configurator:
  manifest: /media/projects/<slug>/<file>.json   # манифест ролей и вариантов
  vehicles:                    # машины гаража (раздел VEHICLES), необязательно
    - manifest: /media/projects/<slug>/<car>.json   # файлы уровней — рядом с model.src
      rotation: 90             # разворот этой машины (дефолт — model.rotation)
      thumb: /media/projects/<slug>/vehicles/<car>.webp
      # name: Coupe            # подпись (дефолт — слаг манифеста прописными)
  garage:                      # необязательное окружение вокруг машины
    src: /media/projects/<slug>/garage.glb
    scale: 1                   # единицы окружения (дефолт 1)
    rotation: 0                # разворот вокруг Y, градусы (дефолт 0)
    fit: 0.77                  # кадрирование камеры в гараже (дефолт — fit модели)
    zoomMax: 1.26              # предел отъезда, в долях кадра (дефолт — zoomMax модели)
    # orbitFrom: 15            # дуга облёта, градусы: только вдвоём и только
    # orbitTo: 165             # если в стене проём — без них полный круг (случай rp-grand)
    tiltFrom: 3                # пределы по высоте, градусы над горизонтом машины
    tiltTo: 38                 # (дефолты 3 и 50; 90 — строго сверху)
  audio:                       # музыка зала (необязательно)
    tracks:                    # очередь; вместо неё можно один `src`
      - src: /media/projects/<slug>/audio/<track>.mp3
        title: Night Street Racing
        artist: GVIDON         # необязательно
    volume: 0.35               # громкость, до которой доходит появление (0…1)
    fadeIn: 4                  # секунд на появление (дефолт 4)
```

- Кейс с `configurator` в шапке показывает обложку, а гараж
  (`app/components/projects/ProjectCarConfigurator.vue`) идёт под шапкой полосой
  во всю ширину окна ростом в экран. Поверх сцены — игровой HUD: слот машины,
  строка контекста, меню разделов, радио и технический монитор (changes-log §61).
- Разделы HUD (`VEHICLES`, `BODY`, `PAINT`, `DECALS`, `MATERIAL`, `TECH`) — состояния
  одного слоя, не страницы. Выбор детали в `BODY` подводит камеру к ней
  (`app/utils/garageCamera.ts`, ракурсы — `GARAGE_FOCUS`), открытая панель
  сдвигает проекцию, чтобы не накрывать машину. Тёплый свет, дымка и контактная
  тень гаража — `app/utils/garageAtmosphere.ts`.
- Панель строится по манифесту (копия из экспортёра рядом с GLB): роль ноды →
  группа кнопок, вариант → кнопка, ключи `lods` → уровни детализации. Вторая
  машина и новый вариант правок кода не требуют. Имена нод в манифесте могут
  содержать точку из Blender (`Wheel.001`): вьювер приводит их к виду, который
  отдаёт загрузчик three (`nodeKey` в `app/utils/carVariants.ts`).
- `garage` ставит машину внутрь окружения: машина садится на пол зала, камера
  ограничена стенами — отъехать дальше, чем позволяет коробка, нельзя
  (расстояние считается от машины до каждой стены: зал редко бывает симметричен).
  Пол ищется пробами по габариту машины (`app/utils/garageFloor.ts`): низ
  габарита гаража — это плинтус по периметру, а не плита, и посадка по нему
  утапливает колёса внутрь пола (у зала NFS разница 13 см). Пробы идут сеткой
  сверху вниз, побеждает самая населённая группа попаданий — так пол не путается
  ни с реквизитом на полу, ни с лампой над машиной. Без `garage` конфигуратор
  работает как и раньше, на прозрачном фоне. Окружение грузится параллельно
  машине, поэтому лишнего ожидания не добавляет.
- `fit`/`zoomMax` в гараже переопределяют кадрирование модели: большой зал
  снимается ближе, потому что реквизит стоит в нескольких метрах от машины и на
  общей дистанции камера упирается в него (у гаража rp-grand чужая машина стоит
  уже в 6 м, поэтому дистанция держится в районе 6,0 м, а отъезд ограничен 6,9 м).
  Оба поля необязательны: без них берутся `model.fit`/`model.zoomMax`.
- `orbitFrom`/`orbitTo` ограничивают облёт камеры дугой (градусы, отсчёт от +Z сцены
  как у долготы в OrbitControls). Задаются только вдвоём — одна граница это не
  дуга, а половина круга. Поле нужно окружению с проёмом в стене: только тогда
  камера в него не заходит. Замкнутому залу стопор не нужен, поэтому у rp-grand
  дуга не задана и камера обходит машину полным кругом.
- Автоповорота в конфигураторе нет: камера стоит, пока её не потянут мышью.
  Витринный поворот остаётся у обычного вьювера в шапке кейса — там модель одна
  и её никто не рассматривает по частям. Следствие для контента: `autoRotate`
  и `autoRotateSpeed` в блоке `model:` конфигуратор не читает.
- `tiltFrom`/`tiltTo` — пределы по высоте в градусах над горизонтом машины (0 —
  камера на её высоте, 90 — строго сверху). В гараже выше предела камера уходит
  под крышу и смотрит не на машину, а на её перекрытие, а ниже нуля — под пол,
  поэтому по умолчанию 3…50°, а у высокого зала предел ниже (у rp-grand 38°:
  над машиной висит крыша примерно на 4,5 м). Без окружения вертикаль не
  ограничивается вообще.
- `audio` — музыка зала: очередь `tracks` или один `src` (`app/utils/garageAudio.ts`).
  Очередь листается кнопками радио и идёт дальше сама, один трек крутится петлёй. Трек не
  грузится вместе со страницей: адрес отдаётся элементу только когда сцена уже
  собрана (модель, уровни и текстуры на месте), поэтому музыка не спорит с ними
  за канал — в сетевой панели `night-street-racing.mp3` идёт после GLB и карт.
  Играет тихо и сам набирает громкость с нуля за `fadeIn` секунд (резкий старт
  в фоне слышен как «врубилось»), зациклен и выключается кнопкой с нотой в углу
  сцены: перечёркнутая нота — тишина. Браузер без действия пользователя звук не
  отдаёт, и тогда трек встаёт на взвод: первый же клик, тап или клавиша на
  странице его запускают, кнопка выглядит так же выключенной. Без поля звука нет
  вовсе — кнопки тоже. Треки приходят из библиотек в 256 кбит/с (4 МБ на две
  минуты); ужимать их — `node scripts/squeeze-audio.mjs in.mp3 out.mp3
  --bitrate=96` (у rp-grand 4,27 МБ → 1,60 МБ).
- Уровни детализации садятся по LOD0: смещение считается один раз по подробному
  уровню (он один с колёсами) и применяется ко всем остальным. Посадка по
  собственному габариту уровня утапливала бы LOD1/LOD2 в пол, потому что колёс
  в них нет.
- Колёса держатся в самой сцене (`lod-wheels`), а не внутри уровня: вьювер
  переносит ноды роли `wheel` с подробного уровня через `attach` (мировые
  координаты сохраняются) и показывает их на любом уровне. Если у уровня есть
  свои колёса, показываются они, а перенесённые гасятся. Счётчик трисов и draw
  calls считает **только модель**: колёс в ней нет (машина сдана без них),
  а стоящие в кадре подставил вьювер — поэтому рядом с числами стоит оговорка
  «Учёт без колёс» (`statsNote`). Иначе панель показывала бы цифру, которой
  в файле кейса нет: на подробном уровне из 30 526 трисов 23 016 приходились
  на четыре подставленных колеса.
- Окраска — три независимые оси (цвет, узор, покрытие) поверх UV-маски GLB;
  сцена и выбор переживают смену языка, возврат в кейс (`carConfiguratorCache`)
  и перезагрузку страницы: выбор пишется в `localStorage` через
  `app/utils/carPaintStorage.ts` (ключ `rp-grand:car-paint`) при каждом изменении
  и восстанавливается в `onMounted` до сборки сцены. id, которых в палитре уже
  нет, молча заменяются дефолтом резолверами; сломанный или недоступный storage
  не ломает конфигуратор. SSR всегда рендерит дефолт — восстановление только
  на клиенте.
- **Выбор окраски живёт в одном месте (`paint` в конфигураторе), а красится
  всё собранное сразу** — `carPaintHandles(viewer)`: видимый уровень плюс все
  уровни из `lodModels`. Иначе окраска расходится с панелью: материалы уровня
  живут в его же хендле, и уровень, собранный раньше, остаётся в прежней краске,
  а колёса живут в сцене отдельной группой и держат материалы подробного
  уровня — после подмены уровня машина меняет цвет, а колёса нет. Вызывается
  везде, где меняется выбор или подставляется другая геометрия: смена окраски,
  смена уровня, возврат к закэшированной сцене.
- **Игровой мобильный HUD конфигуратора.** Конфигуратор — это экран гаража, а не
  продолжение карточки сайта: на узких экранах кадр держит пропорцию 16:10,
  поэтому мобильная камера не отъезжает из-за искусственной высоты 560 px. Внутри
  кадра остаются только машина, компактный статус, музыка, нижний dock разделов
  и панель кастомизации. Технические трисы, draw calls, оговорка про колёса и
  постоянный сброс не являются частью игрового экрана; сброс доступен внутри
  панели. На телефоне разделы показывают иконки без длинных подписей, а панель
  открывается компактным bottom sheet внутри кадра. Стили и breakpoint находятся
  в `ProjectCarConfigurator.vue`, а не в глобальном layout сайта.
- Набор печатей и превью к ним собирает `scripts/fetch-car-textures.mjs`; новая
  печать добавляется строкой в `CAR_PATTERNS` плюс подписями в i18n.
- Обложка кейса — кадр самого гаража, а не постановочный рендер: скриншот
  живого экрана обрезается под карточку скриптом
  `node scripts/make-rp-grand-cover.mjs <скриншот.png> [--crop=x,y,w,h]`
  (по умолчанию окно обводит HUD целиком — машина, ряд разделов и монитор
  в кадре, левые панели и строка контекста за кадром). Исходник в репозитории
  не хранится: это кадр состояния, а не ассет. Так карточка на главной и постер
  вьювера показывают то же, что соберётся на странице через секунду.
- Паритет уровней детализации проверяет `pnpm check:lods`
  (`scripts/check-lod-parity.mjs`, входит в `pnpm check`): по каждому кейсу
  с `configurator.manifest` читаются манифест и GLB уровней и сверяются ноды,
  роли, колёса, UV-наборы и цифры манифеста. Упрощение уровня допустимо, только
  если оно объявлено в манифесте полем `parity` (id уровня → причина);
  молчаливое расхождение (или лишняя запись в `parity`) — ненулевой код возврата.
  Так новая выгрузка без UV0 или без колёс находится проверкой, а не глазами
  в превью.
- Требования к моделям (оптика отдельным материалом, лишние UV-наборы, колёса,
  уровни детализации) — в `docs/3d-viewer-spec.md` §5.

## 6. Как менять сайт (общий порядок)

1. **Тексты/кейсы** → правки в `content/**`, `i18n/locales/*.ts`. HMR, сервер
   перезапускать не нужно.
2. **Стили** → `app/assets/css/main.css` (токены `--site-*`, темы).
3. **Схема контента** → `content.config.ts`. ⚠️ После правок схемы **сервер надо
   перезапускать**; правки только в `content/` подхватываются горячо.
4. **Компоненты/логика** → SFC в `app/components/`, утилиты в `app/utils/`,
   `app/composables/`. Проверяй автоимпорт (см. §4).
5. **Новые медиа** → кладём файл в `public/media/…` — папка `public/` отдаётся
   статикой, дополнительная синхронизация не нужна.
6. После изменений: `pnpm lint` и `pnpm typecheck` — чисто. Перед продом —
   `pnpm build`.

### Известные подводные камни

- **Кэш контента** иногда слетает (пустая страница/старое содержимое):
  `rm -rf .data/content` + перезапуск dev-сервера.
- **Двоеточие в `alt` ломает YAML**: бери строку в кавычки.
- **PNG с битым EXIF** не читается ffmpeg — используй ImageMagick.
- **`canvas { max-width: 100% }`** в глобальных стилях режет размер канваса
  WebGL: у вьювера в scoped-стилях должен быть `max-width: none`.
- Канвас добавляется в DOM через JS и не получает `data-v-xxx`: opacity
  вьювера управляется из JS (`attachViewer`/`detachViewer`), а не scoped-CSS.

## 7. 🚨 Что никогда не должно попасть в открытый доступ

**Папка `public/` — единственное, что сайт отдаёт наружу.** Всё остальное
в репозитории — внутреннее. Ничего из перечисленного ниже нельзя:

- класть в `public/`;
- ссылаться с сайта (URL, `<img>`, `fetch`, прелоады);
- упоминать/раскрывать в кейсах, текстах и карточках;
- поститься в публичные репозитории/гитхаб.

### Запрещённые к публикации пути и данные

| Путь / данные | Почему опасно |
|---|---|
| `docs/**` | Внутренние ТЗ, планы, инвентарь — рабочие мысли, не для посетителей |
| `docs/content-decisions.md` | **Особо секретно**: цены (бюджет 30 000 ₽, нижняя граница 10 000 ₽), внутренние имена, правила, что нельзя публиковать. Само существование этих цифр — внутренняя информация |
| `docs/3d-viewer-spec.md`, `docs/backlog.md`, `docs/changes-log.md` и др. | Рабочая документация и история решений |
| `CASE_TEMPLATE.md` | Внутренний шаблон с правилами и чек-листами |
| `README.md` (опционально) | Технические детали для разработчика, не для публики |
| `.freebuff/` | Логи dev-сервера, логи превью, `run.md`, `project-id`, БД диалогов (`desktop-v2.db*`) — **все разговоры о сайте**, чувствительно |
| `.data/`, `.nuxt/`, `.output/`, `.cache/`, `.vite/` | Сборки и кэш контента (внутри может лежать содержимое всех страниц) |
| `logs/`, `*.log`, `dev-server.log` | Логи с путями, ошибками и деталями |
| `.env*` (кроме `.env.example`) | Секреты и конфигурация |
| `node_modules/`, `.pnpm-store/` | Зависимости (не публиковать вручную) |
| Личные переписки, внутренние имена, платежи, споры | Полный список запрещённого контента — `docs/content-decisions.md` §8 |

### Как это обеспечено технически

- **Nuxt отдаёт наружу только `public/`.** Проверено: `/docs/…`, `/CASE_TEMPLATE.md`,
  `/README.md`, `/nuxt.config.ts`, `/content.config.ts`, `/.env` → все 404.
  Внутренние файлы не попадают на сайт сами по себе — опасно только сознательно
  положить их в `public/`.
- **`.freebuff/` (логи, БД диалогов, `run.md`) игнорируется git** корневым
  `.gitignore` (репозиторий лежит на уровень выше папки сайта).
- **`docs/` и `CASE_TEMPLATE.md`** лежат в папке сайта и в git — это внутренняя
  документация для разработчика. В публичный репозиторий их пушить нельзя
  (см. правила ниже).

### Правила на будущее

- **Новые внутренние документы** (мысли, ТЗ, планы, обсуждения) класть **вне
  `public/`**: в `docs/` или вообще вне папки сайта. Не ссылаться на них из кода.
- **Разговоры/правила работы** (типа этого диалога) — **не привязывать к сайту**:
  не класть в `public/`, не линковать, не цитировать в контенте.
- Перед деплоем/публикацией репозитория прогонять чек: ничего из таблицы выше
  не попало в `public/` или в коммит.
- Если нужен «открытый» вариант документа — создавать его отдельно
  (например, стандарт 3D для клиентов в `docs/3d-viewer-spec.md` §5 уже
  частично публичный), не переиспользуя внутренний файл.
