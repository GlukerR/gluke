# RP Grand — интерактивный 3D-конфигуратор автомобилей (план для реализации)

> Статус: **план.** GLB-экспорт всех семи машин готов и проверен, сайт пока не тронут.
> Этот документ — рабочий источник для следующего агента/разработчика: что уже есть,
> что делать по фазам, где лежат данные, какие есть подводные камни и ограничения.
> Формат — по образцу `docs/3d-viewer-spec.md`.

---

## 1. Контекст и цель

Сайт — портфолио студии GLUKE (Nuxt 4, Vue 3, TypeScript, three@0.185 уже в
зависимостях). Продаваемая услуга — «3D-модели для веб-вьюверов» (GLB, WebGL,
интерактивный просмотр), см. `content/site/ru.yml`.

Цель: кейс «RP Grand» с **интерактивным конфигуратором** — не просто «покрутить
модель» (это уже умеет `ProjectModelViewer.vue` для getic/softlogic), а живая
демонстрация подготовки game-ready ассетов к real-time:

- переключение вариантов обвеса (бамперы, юбки, спойлеры) — модульность ассета;
- смена цвета **без текстур** — перекраска шейдером по UV-маске;
- LOD (High/Medium/Low) с живым счётчиком полигонов;
- техническая панель (трисы, draw calls, размер файла) — факты о своей работе.

История вопроса, инвентаризация ассетов и правовой разбор — вне репозитория
(Obsidian-ваулт), в репозитории держим только сам план и код.

## 3. Ключевые технические факты (подводные камни)

1. **В GLB ВСЕ варианты видны одновременно.** Экспортёр снимает hide со всех
   объектов перед выгрузкой (`ob.hide_set(False)`), поэтому три бампера, три юбки
   и три спойлера лежат друг на друге в одном файле. Простой вьювер без доработки
   покажет наложение/кашу. **Любой рендер машины обязан сам гасить невыбранные
   ноды** (`node.visible = false`), кроме активной конфигурации.

2. **Цвет — без текстур.** UV1 каждой детали разложена по четырём квадрантам
   (маска 2×2, генерируется при экспорте): краска / второй цвет / пластик-хром /
   чёрный (стыки панелей). Перекраска — во фрагментном шейдере: смотрим, в какой
   квадрант UV1 попал фрагмент, подставляем цвет. Второй UV-канал — под наклейки.
   Текстур заказчика в проекте нет и не будет.

3. **Колёс нет вообще** (сдавались без колёс, у заказчика свой атлас). Моделить
   отдельно: 2–3 комплекта дисков + одна шина, 600–1200 трисов на колесо —
   в ту же бюджетную логику. До готовности колёс машина показывается без них
   (в игре было так же), либо с временными заглушками.

4. **LOD2 в «Low»-качестве выглядит как каша** — не использовать его как «Low
   для мобилки». Варианты: показывать LOD2 только в технической панели как
   иллюстрацию, либо Mobile → LOD1 + упрощённое окружение.

5. **Skyline (`coupe-jdm`) не брать первым** — в файле остался персонаж
   заказчика и битый пивот правой двери (экспортёр это чинит при экспорте, но
   для MVP нужен чистый кандидат). Кандидаты на первый вьювер: `coupe-gt`
   (DBS), `roadster` (Mercedes SL) — полный набор 3+3+3+3, чистые пивоты.

## 4. Правовые рамки (обязательно для текстов и публикаций)

До письменного ответа заказчика (письмо-запрос отправлено 09.09.2026) действует
простое правило: **про свои модели говорить можно, цитировать требования
заказчика — нет.**

- ✅ Можно: показывать модели и конфигуратор, счётчики полигонов своих моделей,
  факты «делал автомобильные ассеты для мобильной open-world игры».
- ❌ Нельзя: цифры и схемы из ТЗ заказчика как его требования, его текстуры,
  цитаты переписки (Discord), имена брендов/марок, названия игры и компании
  до подтверждения.
- GLB раздаётся в браузере — решение принято осознанно (модели и так извлекаемы
  из вышедшей игры), защиту не выдумываем, LOD0 отдаём как есть.

В тексте кейса: «vehicle assets for a mobile open-world game», без марок.
Техническое описание — только о своей работе (моделирование, оптимизация,
модульность, LOD), без ссылок на пайплайн заказчика.

## 5. Фаза 0 — кейс на сайте с обычным вьювером (без нового кода)

Самое простое и первое. Публикует работу уже сейчас, конфигуратор строится потом.

1. **GLB «дефолтной конфигурации».** Нужен файл, где видна одна аккуратная
   сборка (например `a/a/a`, спойлер off). Два пути:
   - доработать `export_car.py` (флаг `--default-config`: оставить только
     выбранные варианты) и прогнать в Blender 3.6 — аккуратно, навсегда;
   - либо обрезать лишние ноды из готового GLB скриптом
     (`npx gltf-transform` / ручной разбор GLB-чанков) — быстрее, но одноразово.
   Решение — см. «Открытые вопросы».
2. **Обложка/постер** из готового рендера: JPEG 16:9, 1680×945, ≤200 КБ
   (по `CASE_TEMPLATE.md`). Рендеры — `D:\Work\Clients\GAME_ART\RP Grand\из портфолио\`.
3. **Файлы в репозиторий** (копии):
   `public/media/projects/rp-grand/<slug>-default-lod0.glb` + обложка
   `rp-grand-cover.jpg`. `public/` отдаётся статикой; `scripts/sync-media.mjs`
   в текущем репо больше нет — новые файлы попадают в прод автоматически.
4. **Кейс** `content/projects/ru/rp-grand.md` + `en/rp-grand.md` по шаблону:
   - `position: 30` (energy-fill — 29), `categories: [webgl]`;
   - `model:` в шапке (по образцу `getic.md`) — постером вьювера служит обложка;
   - `metrics` — ровно 3, без годов в подписях;
   - тело «Задача / Ход работы / Результат»: про модульность (варианты бамперов,
     юбок, спойлеров), LOD0/1/2, перекраску без текстур, что модели приняты и
     вошли в вышедшую мобильную игру. Без марок и без ТЗ-цифр заказчика.
5. **Проверки:** `pnpm validate:content && pnpm lint && pnpm typecheck`,
   затем `pnpm lastmod`.

Критерий приёмки: страница кейса с вращающейся машиной, постер → кроссфейд,
ленивая загрузка, EN/RU, тёмная тема.

## 6. Фаза 1 — конфигуратор (MVP)

Новый компонент `app/components/projects/ProjectCarConfigurator.vue`
(или расширение `ProjectModelViewer` опциональным режимом — решить на этапе
реализации; склоняемся к отдельному компоненту, чтобы не усложнять общий вьювер).

Поведение:

- Загрузка — как в `ProjectModelViewer`: динамический `import('three')`,
  отложенный старт в простой браузера, постер, кэш вьювера, тач-политика.
- После загрузки GLB: **погасить все вариантные ноды**, кроме выбранных.
  Группы: `body kit` = один из `bumper_front_*` + один из `bumper_rear_*` +
  один из `skirt_*`; `spoiler` = один из `spoiler_*` или none.
- Панель конфигурации рядом со сценой:
  - Body kit: Stock / Sport / Racing;
  - Spoiler: None / GT / Carbon / Racing (наполнение — из фактических нод);
  - (позже) Wheels, Paint.
- Живой счётчик: сумма трисов выбранной конфигурации (брать из манифеста
  `<slug>.json` по нодам, или считать `geometry` при загрузке).
- Строки UI — в `i18n/locales/{ru,en}.ts`.

Данные о вариантах для UI лучше не хардкодить, а читать из манифеста
(`<slug>.json`, копия рядом с GLB) — тогда вторая машина подключается одним
файлом.

## 7. Фаза 2 — смена цвета шейдером (без текстур)

- Для `m_Body` — `onBeforeCompile` (или `ShaderMaterial`-обёртка поверх
  стандартного): во фрагментном шейдере по квадранту UV1 подставлять выбранный
  цвет; чёрный квадрант (стыки) оставлять как есть, синий (пластик/хром) —
  нейтральным серым.
- Палитра 4–6 цветов, переключается из панели.
- Это «вишенка» для технического профиля, но не блокер фаз 0–1.
